# Design

## Building blocks

| Block | Responsibility | Depends on | New | Reuse considered |
| --- | --- | --- | --- | --- |
| Transport replay | Charge actual scripted payloads at every declared boundary | Existing CLI fixtures, Git and check runner | yes | Existing byte meters and adversarial recovery cases |
| Managed coordinator guidance | Avoid duplicate mechanics and unnecessary wakeups | Generated original coordinator role and compact reference | no | Existing native host waits and prepare/finish intervals |
| Native launch description | Build a bounded canonical dispatch prompt and identity | Existing immutable full saved brief and effective role policy | yes | Existing worker preparation and output budgets |
| Structured return | Retain bounded claims beside independently observed local facts | Existing contained stage ledger, write validation and evidence judge | yes | Existing private locking, atomic publication and freshness checks |

## Rules

| Rule | Checked by |
| --- | --- |
| Legacy preparation and ordinary task-start output remain compatible | test |
| Generated dispatch retains fresh-host/model/effort requirements and full original packet references | test |
| Every worker retains original instructions, contract and selected skills | test |
| Worker returns never certify native execution, skill loading or task completion | test |
| Malformed, wrong-dispatch, stale or unsafe returns cannot publish successful evidence | test |
| Managed guidance replaces equivalent manual mechanics, not semantic checks | review |
| Reviewer inputs remain neutral and final Git/check requirements remain mandatory | test |
| Replay charges both assignments and every recorded boundary without inventing provider usage | test |
| No model execution or historical evidence mutation occurs in local verification | review |

## Protocol

The explicit dispatch option adds a versioned native launch description to
existing preparation. The default response retains its original schema. The
generated prompt starts with the task label, names the complete saved packet
and SHA-256, and requires original packet and skill loading. It carries effective
model/reasoning and fresh-context requirements, including the Claude native role
when applicable. The host performs the actual launch. A hash of the generated
prompt cannot prove equality to an encrypted native message.

The coordinator ingests a strict, bounded worker-return document after the
worker ends and before finishing its managed interval. Required identity binds
the claim to its original dispatch and saved packet. Local worktree, current
source, policy, write limits and check evidence are independently inspected;
workers need no extra permission or snapshot command merely to fill a return.
Loaded skills, host identity, completion and findings remain explicitly claimed
where they cannot be independently observed. Ingestion leaves the interval open,
runs no check and grants no approval. Full findings, blockers and warnings are
retained or the output budget is refused; they are never silently truncated.
Every finding retains its blocker/major/minor severity so structured hand-backs
cannot erase review-routing or disposition constraints.

Private publication uses the existing pinned Git directory, contained stage
ledger, exclusive lock and atomic write. Repeated ingestion cannot silently
replace changed claims or stale observations. File hashes aid integrity and
bookkeeping, not attestation against another actor with equivalent file access.

## Coordinator behavior

Preparation already resolves effective role/skill policy and orders receipts
before its baseline; finish already checks writes and current evidence. Managed
instructions do not repeat equivalent manual baseline or role-check steps.
Original worker skill reads, semantic red inspection, independent neutral review
and final gate/commit checks remain mandatory. Legacy unmanaged instructions
retain their existing checks.

Resolve stable setup/configuration and optional tool availability once per
applicable session/policy, refreshing after changes or errors. Use available
fallbacks rather than repeatedly invoking a missing tool. Prefer actual native
completion notifications or bounded longer waits; preserve host limits, user
progress, cancellation and real deadlines. Do not infer completion from guessed
rollout files or create a Go daemon that impersonates native host tools.

## Measurement

Fix ordinary assignment transport first. The new deterministic replay uses
actual local Kitsu commands and scripted workers in isolated Git fixtures.
Both paths charge full assignment delivery, dispatch, original packet/skill
reads, returned reports, follow-ups, checks, expansion, rejection, retry and finish
payloads. Checks reused from current evidence differ from new executions.
The fake host records its declared serialized envelopes; unavailable real native
transport and provider usage remain unknown. A scripted semantic oracle tests
specified workflow facts, not model judgment. Negative fixtures include an
interruption after review but before Git: passing code tests cannot become a
completed workflow without the required commit and final current gate.
