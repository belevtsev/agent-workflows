# Streamline opt-in compact handoffs

## Why

The completed Codex pilot exposed repeated request-schema repairs, larger saved
handoffs and late review/Git stages. Transport-size measurements alone do not
establish token savings. The owner requested the first three remedies: typed
reads/searches, direct delivery of canonical briefs and Go-managed stage bookkeeping.

## What changes

- `context read` and `context search` construct the existing versioned request
  in Go and retain its containment, paging, omission and freshness rules.
- `task brief --save --assignment <file|->` saves complete original instructions
  once and prints a small path/hash/model/baseline envelope for native dispatch.
- `task prepare` orders skill selection before its saved baseline and opens a
  private write-check interval. `task finish` validates writes from that baseline,
  records existing check evidence and closes the interval only after validation.
  Explicit abandonment records a reason without granting approval.
- Help, completion, README, how-to guidance and regression tests cover both hosts.

## Scope and authority

Compact mode remains explicit opt-in. The host launches fresh workers; these
commands invoke no model and perform no automatic host configuration. Existing
role permissions, original skill loading, TDD, independent review, approvals,
finding dispositions and the final hooked commit remain required. Private
stage receipts prove only the local checks they record, never task completion
or an independent review. No new paid pilot is authorized or run.

The existing pilot, frozen binaries, inputs, measurements and conclusions remain
unchanged. This change makes no measured task-wide token-saving claim.
