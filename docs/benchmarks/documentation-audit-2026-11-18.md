# Kitsu documentation and diagram audit

**18 November 2026.** The Codex and Claude Code quick starts describe the released plugin correctly. A developer following links deeper into the guides can still configure the wrong check, get an error while resuming a daily task, or look for verification evidence in the wrong JSON object. The diagrams render correctly. Three need changes to their content.

Reviewed [published main](https://github.com/belevtsev/kitsu/tree/00f74f454b3e910eccd80b14910ebb78548c796f) and the [v0.0.2 release](https://github.com/belevtsev/kitsu/releases/tag/v0.0.2). Only documentation and the changelog differ between the two revisions. The command reproductions used the published Linux binary in disposable Git repositories.

## Fix first

The findings below describe the pinned revision. The updated [daily task walkthrough](../task-harness.md#how-a-daily-task-runs) and [ticket delivery diagram](../task-harness.md#deliver-a-bug-ticket) cover the two missing views. The [managed workflow](../workflow.md#the-flow) and [compact handoff](../compact-context.md) show the corrected paths.

The [updated command reference](../cli-reference.md#kitsu-check-add) places Kitsu options before the child command. A regression test runs the verification example from terminal help and checks that a change to `README.md` makes the new check required.

| Where a developer gets stuck | Observed behavior and correction |
| --- | --- |
| Declaring a verification check | The help synopsis places Kitsu options after the child command. Following it with `--verify`, `--expect` and `--when` returned success and saved all three as child arguments. The saved check had `Verify: false`. Move Kitsu options before `--` in the **help generator**, regenerate the reference, and test the resulting declaration. The same ordering problem appears in `task test`. [Check synopsis](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/docs/cli-reference.md#L1526) · [Help generator](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/internal/cli/ux_help.go#L75) |
| Starting or resuming a normal plugin task | The shipped task skill defaults to the daily harness. The workflow guide and walkthrough still suggest a plain invocation starts the seven-role OpenSpec workflow. On a saved daily plan, `kitsu task check ID` and `kitsu task show ID --compact` both failed looking for an OpenSpec change. `kitsu task next ID --brief` and `kitsu task show ID --json` succeeded. Label managed-only examples, and use the daily commands in the general guide. The interactive launcher also saves a resumable ID after preflight, whereas print and JSON previews just prepare the handoff. [Shipped skill](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/skills/task/SKILL.md#L18) · [Workflow guide](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/docs/workflow.md#L5) · [CLI guide](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/docs/cli.md#L53) · [Launcher guide](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/docs/operations.md#L141) |
| Reporting a verified commit | The daily guide tells readers to find `commit_evidence` in `task receipt ID --json`. It also says gate removal deletes evidence. Ordinary uninstall retains the records. Deletion requires `--purge`. Reconcile the reference with the parser and uninstall output. [Configuration guide](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/docs/operations.md#L883) · [Accepted keys](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/internal/decl/decl.go#L100) · [Removal guide](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/docs/operations.md#L961) · [Uninstall behavior](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/internal/cli/uninstall.go#L38) |

To reproduce the first finding, use a disposable repository with `version = 1` in `kitsu.toml`. Both declarations succeed on v0.0.2.

```sh
kitsu check add after -- true --when '*.go' --expect 'expected output' --verify
kitsu check add before --when '*.go' --expect 'expected output' --verify -- true
kitsu check list --json
```

Inspect `Checks`. The `after` entry passes the options to `true` and has `Verify: false`. The `before` entry has `Run: ["true"]`, `When: ["*.go"]` and `Verify: true`.

For example, Codex uses `--host codex` on macOS/Linux or `-AgentHost codex` on Windows. The provider-specific README already passes the correct flags and shows start and resume in both hosts. [Pinned examples](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/docs/release-install.md#L48) · [Codex quick start](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/README.md#L20) · [Claude Code quick start](https://github.com/belevtsev/kitsu/blob/00f74f454b3e910eccd80b14910ebb78548c796f/README.md#L121)

## Verification and regression coverage

The repository documentation checks, generated-reference test and focused harness scenarios passed. All 89 help sections match the released CLI text. That agreement let the argument-order defect appear in both help and docs. The five SVGs passed Archify validation and fresh browser export. Their exports match the committed files apart from trailing whitespace. Light and dark renders had all label bounds inside the viewboxes. This audit covered the published Linux CLI, code and release assets. Interactive provider sessions and fresh macOS and Windows installations were outside this run.

For the next change, execute the documented `check add` form and assert its saved fields, run the public resume examples on a daily task, and assert that each documented JSON field comes from the named command. Check the managed diagram’s review-to-delivery path against the existing stage rules when regenerating the SVGs.
