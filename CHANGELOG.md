# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

This is the v3.0.0 breaking change: the v2 installer is removed, and Claude Code
and Codex get the skills from plugins. v2 users run `cw migrate-v2` with the new
`cw` before installing the plugins; see "Moving from v2" in `docs/operations.md`.

### Breaking

- The Go module path is now `github.com/belevtsev/agent-workflows/v3`, so `go install …@latest` can resolve v3 release tags. The old install path without `/v3` (`go install …/agent-workflows/cmd/cw@…`) no longer gets updates: its `@main` and `@latest` queries fail with a module path mismatch; install with `go install github.com/belevtsev/agent-workflows/v3/cmd/cw@main` (or `@latest` once the first v3 tag exists). Code that imports `github.com/belevtsev/agent-workflows/...` must import `github.com/belevtsev/agent-workflows/v3/...`.

### Added

- Eval suites are checked in CI and run on a schedule: `go test ./evals/...` validates every case's files, grader regexes, graded paths and dispatched agents offline; `.github/workflows/evals.yml` runs each suite weekly or on demand with a 5-dollar ceiling per suite and a 0.8 pass floor when `ANTHROPIC_API_KEY` is set; and a mutant gate fails a test-engineer run whose authored tests pass with any of the case's `testdata/impl-mutants/*.patch` applied. See `evals/README.md`.
- The spec-writer and spec-reviewer agents under `agents/`, with role contracts that write and review OpenSpec-compatible change folders (`openspec/changes/<change-id>/` with `proposal.md`, spec deltas and `tasks.md`), the policy roles `spec_writer` and `spec_reviewer`, eval suites under `evals/`, and the seven-role flow (spec writer → spec reviewer → architect → interface contract → implementer ∥ test engineer → reviewer → `cw task verify` → commit) in `skills/task-orchestration/SKILL.md` and `references/contracts/README.md`.
- `cw task abandon --task DIR --reason TEXT` writes a terminal `abandonment` revision; an abandoned record accepts no further revisions and never gates `git commit` or `git push`. `cw` releases before this one cannot read an abandoned record.
- The commit gate asks (`permissionDecision: "ask"`) before a commit or push with no task record whose change has two of: more than 300 changed lines, more than one top-level directory, code changed without tests; the plugin option `small_task_prompt=false` turns this off. It also asks before a push of a verified repository whose working tree has uncommitted tracked changes.
- `codebase-design` reference "building blocks": reuse before writing, four kinds of block (value, decision, adapter, composition) with the test layer for each; the architect, implementer and test-engineer contracts now check for it.
- Folder guides: `skills/README.md` (catalog kept in sync with each SKILL.md by `catalog_test.go`), `docs/README.md` (index), `docs/agents.md` (agent roster and contracts), `third_party/README.md` (vendored packs and the Go fork); `.github/CODEOWNERS`, Dependabot for Actions and Go modules, `.editorconfig`.
- The architect, implementer and test-engineer agents under `agents/`, with role contracts in `skills/task-orchestration/references/contracts/`, an end-to-end testing reference in `skills/test-strategy/references/e2e.md`, the policy roles `architect`, `implementer` and `test_engineer`, and eval suites under `evals/`.
- `cw hook pre-publish` and `cw hook session-start` with `hooks/hooks.json`: the Claude Code plugin loads `global/AGENTS.md` at session start (optionally with a cached `cw doctor --summary`) and denies `git commit` and `git push` while an open substantial task record for the repository has no passing `cw task verify` on the current source bytes; `cw task verify` now records that content digest as `verification.source_sha256`, which `cw` releases before this one cannot read, so hosts that share a task store need the same `cw`. The gate fails open and the plugin option `enforce_verify=false` disables it. See `docs/hooks.md`.
- Root MIT `LICENSE`, `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md` and GitHub issue and pull request templates.
- Plugin manifests for both hosts: `.claude-plugin/` (Claude Code marketplace and plugin) and `.codex-plugin/` plus `.agents/plugins/marketplace.json` (Codex). Install with `claude plugin marketplace add belevtsev/agent-workflows` and `claude plugin install agent-workflows@agent-workflows` in Claude Code, or `codex plugin marketplace add belevtsev/agent-workflows` and `/plugins` in Codex; the Go pack is the `cc-skills-golang` plugin in the same marketplace.
- `third_party/cc-skills-golang/UPSTREAM` records the fork's upstream version and commit and how to refresh it.
- `cw keys set NAME | unset NAME | status` saves, removes and reports the adviser keys (`TYPESAFE_API_KEY`, `SUBQ_API_KEY`, `OPENAI_API_KEY`); `set` reads the value from standard input or `--from-env VAR`, never from the command line.
- `cw install --host codex [--from DIR]` links every `skills-manifest.json` registration from a checkout (default `$XDG_DATA_HOME/agent-workflows/src`) into `~/.agents/skills/<name>`, writes the `global/AGENTS.md` block between `<!-- agent-workflows-start -->` and `<!-- agent-workflows-end -->` in `$CODEX_HOME/AGENTS.md`, and prints the recommended `config.toml` settings from `global/codex-defaults.toml` without editing that file. Re-run it after `git pull` to update. `cw uninstall --host codex` removes the links and the block, also after the checkout is deleted. There is no state, journal, snapshot or rollback.
- `cw migrate-v2 [--dry-run]` removes a v2 installation: the symlinks in `~/.claude/skills/`, `~/.claude/agents/cw-*.md`, `~/.agents/skills/` and `~/.local/bin/cw` that point into the v2 state directory, the managed block in `~/.claude/CLAUDE.md` and `$CODEX_HOME/AGENTS.md` (and in the host homes v2 recorded) while v2's `state.json` or `journal.json` remains, and `current`, `releases`, `bases`, `runtime`, `state.json` and `journal.json` in the state directory. It keeps `workflow-tasks/` and does not touch the model keys v2 wrote into `settings.json` or `config.toml`, or the `PATH` line in a shell profile. A `--state-dir` without any v2 entry has nothing to migrate, and one with release entries but neither `state.json` nor `journal.json` must be named `agent-workflows`.
- Release archives `cw_<tag>_<os>_<arch>.tar.gz` for darwin and linux on amd64 and arm64, with `SHA256SUMS`, built by goreleaser (`.goreleaser.yaml`); `go install github.com/belevtsev/agent-workflows/v3/cmd/cw@main` builds from source.

### Changed

- `cw task start` refuses a substantial plan without a check bound to a requirement. `cw task verify` on a changed substantial task needs the latest run of some check passed at the current source and, when the selected path holds `go.mod`, a passed direct `go test` run whose `./...`, `./pkg` or `./dir/...` pattern covers each changed package (any file in its directory or `testdata/`; a non-Go file in a directory without Go files belongs to the nearest ancestor package); a changed `go.mod`, `go.sum`, `go.work` or `go.work.sum` needs `./...`. A run earns credit only when every flag in its argv and its `GOFLAGS` (split like cmd/go, recorded with compiler and linker flag values redacted) is on an allowlist of flags that cannot skip or replace tests, with `-count` at least 1 and a `test.` prefix only on flags go test passes to the test binary; `-run`, `-skip`, `-args`, `-c`, `-n`, `-exec`, `-toolexec`, `-overlay`, `-ldflags`, `-gcflags`, `-asmflags`, `-C`, unknown flags, a pattern after a flag that follows a pattern (`go test ./a -v ./b` tests only `./a`), wrappers (`make`, scripts), `GO.EXE` and Windows-style `.\pkg` patterns earn none. A check's argv is stored verbatim, so keep secrets out of it. The rules live in the language-neutral registry `internal/langpack`, with Go as its first pack. Open substantial tasks whose plan has no checks, or, in a Go module, whose checks run tests only through wrappers or with flags off the allowlist, cannot meet this: add a direct `go test` check and restart them.
- Worker findings carry `severity` (`blocker`, `major` or `minor`), required in review handoffs; findings recorded earlier read as `major`. `cw task verify` lists every rejected blocker or major finding as a limitation (first, as `rejected_findings`, with `--summary`), and a rejected blocker is a problem until a later accepted independent review, whose bundle lists the rejection, completes without re-raising it.
- Claude Code gets the skills and the worker agents only from the `agent-workflows` plugin, and worker briefs use only the namespaced agent types (`agent-workflows:cw-reviewer` and friends). `cw install --host claude` is a usage error that points at the plugin.
- Nothing writes the hosts' model settings any more: `model` and `effortLevel` in `settings.json`, and `model` and `model_reasoning_effort` in `config.toml`, are the user's to set. The README documents the policy defaults.
- Adviser keys are saved with `cw keys set NAME` and checked with `cw keys status`; an adviser is disabled by editing `advisers.disabled` in `preferences.json` in the configuration directory by hand.
- CI (`.github/workflows/ci.yml`) runs gofmt, `go vet` and `go test` on Linux and macOS and validates the plugin manifests; repository content checks moved to `go test ./internal/skillcheck`.
- Worker agent types are namespaced under the plugin (`agent-workflows:cw-reviewer` and friends); the task-orchestration skill carries a `Plugin root:` line so briefs can name absolute skill paths.
- The always-on instruction block (`global/AGENTS.md`, 7,865 to 2,176 bytes) and the `task-orchestration` skill core (`SKILL.md`, 21,293 to 5,473 bytes) carry only the substantial-task threshold and the decision flow; every rule lives in one reference file, test authors and the GitHub worker are dispatched for substantial tasks or on request, and `docs/workflow.md` links the references instead of repeating them.
- Releases are published from pushed `v*` tags instead of on every push to main.
- `.gitignore` no longer hides macOS Finder duplicate files (names with a ` 2` suffix).
- Rendered diagram HTML is no longer tracked. The JSON specs remain.
- `cw consult` and `cw task start` resolve the model policy as `--policy`, then `$CW_MODEL_POLICY`, then `~/.agents/skills/task-orchestration/model-policy.yaml` when present, then the policy embedded in `cw`; the installed release's `current/skills/task-orchestration/model-policy.yaml` is no longer read. The runtime reads only `version`, `consultation.deadline_seconds` (1 to 3600) and `consultation.providers` from it (`internal/modelpolicy`).
- The configuration directory of the runtime commands is `--config-dir`, then `$XDG_CONFIG_HOME/agent-workflows`, then `~/.config/agent-workflows` (`internal/userconfig`); a recorded installation's directory is no longer consulted. `preferences.json` is read for `advisers.disabled` only, and a top-level member other than `version`, `hosts`, `shared` and `advisers` is refused.
- `cw task`, `cw consult`, `cw doctor`, `cw graphify` and `cw metrics` no longer depend on `internal/workflow`.

### Fixed

- Source capture no longer treats a Git repository as a plain folder ("Git identity is unavailable") or drops HEAD or the branch when a Git inspection command does not finish cleanly. Only Git exiting with a failure status, or no `git` on `PATH`, still means the path is not a repository. Any other end of any probe stops capture with one of: `Git inspection timed out after <budget> (git <probe>)`; `Git inspection was killed before it finished (git <probe>)` (detected on Unix); `Git inspection stopped by the caller (git <probe>): <reason>`; `Git inspection could not complete (git <probe>): <cause>`, which covers an unclean finish such as a child process holding Git's output open after Git exited. Each probe now has 60 seconds, still bounded by the caller's deadline, and 10 seconds instead of 100 milliseconds for its output after Git exits: on loaded machines 5 seconds was exceeded, failing `cw task start`, and 100 milliseconds was too short to copy a large listing. `cw hook pre-publish` bounds its Git and source-capture work with a 20 second deadline; a record whose source identity cannot be captured in time is skipped, as when capture fails, while other records can still gate. After a check runs, its source capture gets at most 20 of the 30 seconds for recording the result, so the result is still written when that capture fails or runs out, unless the task lock stays held through the remaining time; a check that passed but whose capture failed or ran out is recorded as `source_changed`.
- The commit gate stays shut while any open substantial record for the repository lacks a passing `cw task verify`; a newer record no longer hides an older open one, and the deny reason names every gating record with its verify and abandon commands. A verified record is finished, and stops gating, once another open substantial record starts, after that verification, from exactly the bytes it was verified on.
- The commit gate ages records by their latest revision instead of their start, so a task worked on for more than 14 days keeps gating.
- From a linked worktree of a record's checkout, the commit gate compares the linked worktree's source with the verified digest instead of the main checkout's.
- The commit gate's hook runs for every Bash command that names git (`Bash(*git*)`) and recognises `git -C DIR`, `command [-p] git`, `env [options] git` (following `env -C DIR`), `sudo`, `timeout`/`nice`/`stdbuf` wrappers, `$(...)` and backtick substitutions (checked from the directory in effect), `sh -c '...'`, `eval` and `\git`.
- The session-start hook says that the verify gate is inactive when `cw` is not on `PATH`.
- `TestRunningChecksRetainEveryTerminalSlotAtRevisionLimit` no longer fails intermittently under `-race`: the check-barrier helpers wait for the test's own lifetime instead of a fixed 15-second accept deadline, and report a check that exits before its barrier instead of timing out.
- `cw metrics import --composition` on a transcript with a 500 KB Bash command of quoted `a<<b` words runs about 4.5 times faster under `-race` and 2 times faster without it. Heredoc markers are now matched only at a `<<` outside quotes. Before, a regular expression found every `<<` that has a marker's shape, and the quoted ones were then discarded. A line that has a marker-shaped `<<` but starts no heredoc (for example a quoted one) is also scanned for quotes once instead of up to twice; a line with no `<<` was already scanned once. Results are unchanged. `TestMetricsCompositionStalePhaseLongCommandLinear` no longer fails on loaded `-race` runners ("import took 17.4s, want under 10s"). Its wall-clock bound is removed. Instead, `TestSplitShellWorkLinear` checks that the splitter's quote-scanning and redirect-search work stays linear in the command length.
- `cw metrics import --composition` no longer slows down quadratically on a Bash command with deeply nested unquoted `(`, `$(` or `$((`. The splitter copied its quote-nesting stack for every line and searched it for every heredoc marker, so 20,000 open parentheses followed by 20,000 lines or `a<<b` markers took 45–115 ms to split, and a million would take several minutes, which Ctrl-C could not stop. Copies now share the stack, and each frame records how many `$((` frames lie under it, so both steps take constant time; the same input now splits in about 5–13 ms. Results are unchanged. `TestSplitShellWorkLinear` now also counts stack frames copied or searched, and covers deeply nested commands.

### Removed

- The v2 installer engine: `install.sh`, the setup wizard (terminal and plain interfaces, presets, `--settings`, `--shell`, `--adopt-personal-skills`), `cw status`, `cw update`, `cw rollback`, `cw recover`, and `cw install`/`cw uninstall` for Claude Code.
- Immutable release snapshots under `~/.local/state/agent-workflows/{current,releases,bases,runtime}`, `state.json` and `journal.json`, release-tag verification, the manager runtime, and `personal-skill-origins.json`. `cw migrate-v2` removes what a v2 installation left behind.
- `cwdev check`, `cwdev release` and `cwdev sandbox`, and `testing/sandbox`; `cwdev eval multilingual` is the only `cwdev` command left.
- `.github/workflows/validate.yml`, which published a release on every push to main.
- The `db-postgres` third-party skill, because its license was ambiguous. The suite now has 36 registrations with 81 entrypoints.
